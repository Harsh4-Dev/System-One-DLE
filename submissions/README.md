## A. typed-decisions leaderboard (about 10 minutes)

**What you are submitting.** A system called **Laya + ADAR-Cal**: the open `convaiinnovations/laya`
checkpoint with one temperature per (question type, number of options), fitted on the benchmark's
*train* split. It changes how confident Laya is, never which answer it picks.

### Before you submit (2 minutes)

- [ ] **The scorer check passes.** `ENTRY.md` ends with `match = True`: our evaluation reproduces the
  published numbers of `laya-typed-decisions` (0.767 / 0.061 / 0.214 vs. 0.766 / 0.062 / 0.213).
- [ ] **Latency.** Open `typed_decisions/laya/metrics.json` from your Kaggle output (inside
  `adar_outputs.zip`) and copy `latency_ms_p50`. If the form asks for it and you don't have the file,
  write "≈133 ms per case (mean, Kaggle T4)": 400 test cases took 53 s in the run log.
- [ ] **Make the link public.** The entry links to `https://github.com/Harsh4-Dev/System-One-DLE`.
  The repository must be public, with the branch merged to `main`, or reviewers see a 404.

### Submit

1. Open **https://huggingface.co/spaces/mayafree/typed-decision-leaderboard** and sign in to Hugging Face.
2. Find the submission form (usually a tab named *Submit* or *Add entry*).
3. Fill it from `typed_decisions/entry.json`:

   | Form field (names vary) | Value |
   |---|---|
   | Model / system name | `Laya + ADAR-Cal` |
   | Base model | `convaiinnovations/laya` |
   | Parameters | `421M` |
   | Accuracy | `0.363` |
   | Brier | `0.2365` |
   | ECE | `0.0214` |
   | KL | `0.4325` |
   | Latency | `latency_ms_p50` from `metrics.json` (state "Kaggle T4, batch 1") |
   | Price | free, open weights, self-hosted |
   | Link | `https://github.com/Harsh4-Dev/System-One-DLE` |
   | Notes / disclosure | the `training_data_disclosure` text from `entry.json` |

4. Submit, then reload the leaderboard and take a screenshot of the row for the deck.

If the Space has no form and asks for a pull request or a discussion instead, open a **Discussion**
on the Space with the `ENTRY.md` table pasted in.

### How to talk about it (keep it honest)

* Say: "Our calibration cut Laya's calibration error by 88% on a public System-One benchmark,
  and our scorer reproduces the leaderboard's own numbers."
* Don't say "we are #1": the board is usually sorted by accuracy, and ours stays at 36.3% because
  calibration never changes the answer. When we checked, the best ECE listed was 0.031; ours is 0.021,
  but a well-calibrated weak model is easy to make, so present it as a calibration result.
* Why not calibrate the stronger `laya-typed-decisions` checkpoint? It was trained on the same train
  split, so temperatures fitted there come out wrong. In our run it cut ECE by 71% but more than doubled Brier (0.061 → 0.148).

## B. Hugging Face model pages (about 5 minutes)

The two heads were already uploaded by the notebook as **private** repos:
`DEV-HV/adar-head-ag-news` and `DEV-HV/adar-head-emotion`.

1. Open each repo on huggingface.co → **Files and versions** → `README.md` → **Edit**
   (or **Add file → Upload files**), and replace it with
   `submissions/huggingface/<repo>/README.md`. Commit.
2. Check the model page: an **Evaluation results** box appears on the right
   (accuracy and macro-F1 from the `model-index` block).
3. **Settings → Change model visibility → Public**, if you want people at the demo to open it.

Or from Python (needs a write token, from `huggingface_hub import login; login()`):

```python
from huggingface_hub import HfApi
api = HfApi()
for task in ("ag-news", "emotion"):
    api.upload_file(path_or_fileobj=f"submissions/huggingface/adar-head-{task}/README.md",
                    path_in_repo="README.md", repo_id=f"DEV-HV/adar-head-{task}")
```
