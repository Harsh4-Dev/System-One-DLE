ADAR: Adaptive Deep Architecture Routing

A small trained decision head that sits on top of the open System-One model Laya and the classic architectures from our syllabus. For every input it answers three questions: what is the answer, which architecture should I trust here, and how sure am I?

This page tells the story in plain language: the problem, the fix, and what improved. Setup, leaderboard and publishing steps are in the repository's docs/ folder.

1 · The problem

Four things go wrong when you train one deep-learning model and ship it.

The biggest model is not always right

58.1% vs 92.2%

Laya zero-shot on Emotion tweets, versus a 1.2M-parameter Bi-LSTM from our syllabus.

Picking one route for every input wastes accuracy

92.5% → 94.9%

AG News: the cheap experts alone, versus a perfect per-input choice that calls Laya on only 8% of inputs.

Strong models are expensive

1.1 ms vs 706 ms

A TextCNN versus Laya, per news article on a CPU.

Even System-One models drift

ECE 0.214

Laya's fine-tuned checkpoint on the public typed-decisions benchmark: its confidence is off by about 21 points on average.

2 · The fix: ADAR

Cheap syllabus models answer first. Only when they are unsure does the input go to Laya and the ADAR head, which combines everything into one calibrated decision.

The ADAR head, in simple words

Think of a meeting with one chairperson. Every input becomes a short row of tokens:

STATE · Laya reads the text OPTION "world"OPTION "sports"OPTION "business"OPTION "sci/tech" EXPERT TextCNNEXPERT RNNEXPERT LSTMEXPERT GRU

Each option token is built from a written description of the label (for example "sports news: games, matches, teams…") plus every expert's vote for it. Each expert token says how sure that expert is. A small 2-layer transformer lets the tokens look at each other (attention), then the head gives three typed outputs:

choice

A probability for every option: the answer.

noul × 4

"Is this expert right on this input?" This sets a per-input routing weight for each expert's vote.

act

"Is my own answer right?" Used to abstain or escalate.

Teaching it to be honest

  • Proper scoring rules (log score + Brier score) reward the head only for reporting its true belief, like a weather forecaster whose "70% rain" should mean rain on 7 days out of 10. Laya's own RLCD training rewards the same thing.
  • Temperature scaling on validation data fine-tunes the confidence after training.
  • Out-of-fold opinions. Each expert is trained three times on different thirds of the data, so the head only ever sees an expert's opinion on text that expert never trained on.

Spending the expensive model only where it helps

The router reads only the cheap experts' signals (how sure they are, whether they agree) and predicts whether they are right. The threshold router escalates below a cut-off chosen on validation data. The REINFORCE router learns the same decision by policy gradient, from reward = 1 if the final answer is right, minus a cost for each escalation.

What the head learned about the architectures

Nobody told the head which expert is better. It worked out a routing weight for each one, per input:

ExpertAvg routing weightReal accuracyAUC of “is it right?”
TextCNN0.16191.7%0.910
Bi-GRU0.16092.4%0.899
Bi-LSTM0.15092.3%0.900
Bi-RNN0.06791.5%0.913

It gives Bi-RNN the lowest weight, the plain RNN, which the syllabus flags for vanishing gradients. Its per-input “is this expert right?” predictions separate right from wrong answers with AUCs between 0.90 and 0.91.

4 · Limits, stated plainly

  • Laya is frozen; ADAR trains only the head.
  • Only text classification is covered so far.
  • On Emotion tweets, ADAR ties the best syllabus network (+0.00 points, CI -0.75 to +0.75).
  • Attention's accuracy gain is not significant; it mainly helps the probabilities.
  • The cascade threshold chosen on validation gives 93.32% on test against 93.46% when always escalating.
  • On typed-decisions, ADAR-Cal re-calibrates Laya's probabilities; it does not change Laya's answers.
